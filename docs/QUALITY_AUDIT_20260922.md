# 구매 기록 검토 사용법

## 가능한 작업
대시보드에서 구매 기록 JSON(최대 1MB, 5,000건)을 열고 매장·MRV 상태·상품/기록 ID로 필터링한다. KPI는 표시된 기록의 합계다. 현재 목록 CSV에는 DEMO 또는 USER_INPUT 출처를 포함하며 수식 시작 문자를 이스케이프한다.

1. /retailer/dashboard에서 입력 예시 다운로드.
2. JSON 배열의 필드를 본인 기록으로 교체. consumerLabel은 이름 대신 익명 식별자 사용 권장.
3. 구매 기록 JSON 선택. 날짜는 YYYY-MM-DD, 포인트는 0~1e12 정수, 기여도는 0~1e9 유한한 수, ID는 고유해야 한다.
4. 필터를 적용하고 CSV 다운로드.

입력은 브라우저 메모리에서만 처리한다. 서버 전송·영구 저장 없음. 새로고침 시 샘플로 돌아온다. 실패한 입력은 기존 목록을 대체하지 않는다.

## 아직 없는 기능
실제 POS 연결, QR 발급·검증·중복 claim 차단, 개인 지갑 원장, MRV 제출·검증, 온체인 앵커링. 관련 화면은 명시적으로 샘플이다. Supabase 환경변수가 존재해도 대시보드의 출처를 실데이터로 변경하지 않는다. MRV 상태는 파일에 적힌 값이며 독립 검증하지 않는다.

## 검증
npm run check: 타입 검사·프로덕션 빌드·23개 테스트 통과. 브라우저에서 샘플 JSON 다운로드/가져오기, 매장 필터, CSV 파일 내용, 빈 검색 결과, 375px 가로 넘침 없음 확인. 실제 고객 데이터나 운영 Supabase 연결은 시험하지 않았다.

현재 lint/test:e2e/hardhat 스크립트는 저장소에 없다. 이번 변경의 계산·입력 검증은 Vitest, 화면은 실제 브라우저로 확인했다. 계약·체인 코드는 이 변경 범위가 아니다.


## 의존성 검사
Next.js 16.3.5 및 잠금 파일 업데이트 후 npm audit 0건(2026-09-22). 업데이트 후 npm run check 재통과. 전체 서비스 보안 인증을 뜻하지 않는다.
